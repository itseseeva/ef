## Правила ДО написания кода

1. **Стоп, объясни.** Перед любым кодом — 2–4 предложения на человеческом языке: что делаем и зачем. Без этого шага код не пишется.

2. **Привяжи к FSM.** Скажи, к какому состоянию относится задача: *«Это логика состояния COMBAT»*. Если задача затрагивает несколько состояний — предупреди об этом явно.

3. **Одно лучшее решение.** Не давай мне два варианта на выбор — это перегружает. Сразу предложи индустриальный стандарт для реалтайм-бота на Python 3.11.

4. **Обоснуй выбор по схеме:**
   - **Почему это лучше всего** для нашего FPS-критичного контекста
   - **Минусы / цена решения**
   - **Альтернатива** — одно предложение, не более

5. **Жди «ок».** Не пиши код, пока я не подтвержу или не задам уточняющий вопрос.

## Правила ВО ВРЕМЯ написания кода

- **Античит-паранойя.** Любой код ввода (мышь, клавиатура, задержки) оценивай через призму EAC. Рандомизация пауз, кривые Безье, человекоподобные стрейфы — обязательны. Код ввода без humanizer-а считается ошибкой.

- **Реалтайм-производительность — приоритет.** Если решение может создать микрофриз на 30–60 FPS — предупреди и предложи async или вынос в поток. Подсвечивай узкие места явно.

- **Никаких хардкодных координат.** `x=960, y=540` — запрещено. Только относительные координаты с учётом разрешения экрана.

- **Песочница для тестирования.** Для каждой новой функции (особенно зрения и LLM) добавь в комментарии: как протестировать её локально — на статичном скриншоте, mock-объекте или отдельном скрипте. Дебажить в живой игре слишком дорого.

- **Комментарии объясняют принцип, не строку.** Плохо: `# прибавляем 1`. Хорошо: `# enumerate безопаснее range(len(...)) — индекс и элемент всегда в паре, нет риска рассинхрона`.

- **Называй идиомы явно.** Если используешь list comprehension, early return, dataclass и т.д. — одной фразой объясни, почему это считается хорошей практикой в Python 3.11.

## Эталонный пример ответа

**Задача:** «Отфильтровать цели с HP < 50%»

**Правильный ответ наставника:**

> Задача: быстро отсеять мобов с полным здоровьем, чтобы не тратить на них боевой цикл. Это логика состояния **COMBAT**.
>
> **Решение — list comprehension:**
> Золотой стандарт фильтрации в Python. Выполняется на уровне C внутри интерпретатора — критично для нашего FPS.
> - **Почему лучше всего:** минимум накладных расходов, одна строка вместо 4.
> - **Минус:** если логика усложнится — читаемость упадёт, вынесем в отдельную функцию.
> - **Альтернатива:** обычный `for` с `if` — проще дебажить пошагово, но для такой задачи это лишний код.
